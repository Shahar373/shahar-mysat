# התקנת הקושחה על הלוויין, צעד אחרי צעד

מדריך למי שצרב פעם את הקושחה המקורית של הערכה ולא יותר מזה. כל צעד אומר מה לעשות ומה אמור לקרות.
אם משהו לא קורה כמו שכתוב, עוצרים ושולחים את 30 השורות האחרונות מהטרמינל.

## מה צריך לפני שמתחילים

- מחשב עם אינטרנט. Windows, Mac או Linux, לא משנה.
- אותו מתאם USB שבו צרבת את הקושחה המקורית של ה-ESP32-CAM, ואותו כבל.
- כבל USB ל-Nano (רק לשלב האחרון, שהוא לא חובה).
- הלוויין עם סוללה טעונה, והכנפיים חופשיות לזוז. הקושחה החדשה מזיזה את הכנפיים כ-12 שניות אחרי הדלקה.

## שלב 1: להתקין VS Code

1. נכנסים ל-https://code.visualstudio.com ומורידים את הגרסה למערכת שלך.
2. מתקינים עם ברירות המחדל ופותחים.

## שלב 2: להתקין PlatformIO בתוך VS Code

1. בסרגל השמאלי לוחצים על סמל ההרחבות (ארבעה ריבועים).
2. בשורת החיפוש כותבים `PlatformIO IDE` ולוחצים Install על התוצאה של PlatformIO.
3. מחכים. זה לוקח כמה דקות, ובסוף מופיעה הודעה בפינה הימנית התחתונה שההתקנה הסתיימה.
4. סוגרים את VS Code ופותחים מחדש. בסרגל השמאלי אמור להופיע סמל חדש, ראש של חייזר. זה PlatformIO.

## שלב 3: להוריד את הקוד

1. מורידים את הקובץ הזה: https://github.com/Shahar373/shahar-mysat/archive/refs/heads/claude/kind-turing-9gexz1.zip
2. מחלצים אותו. מתקבלת תיקייה עם שם ארוך. משנים את שמה ל-`mysat` ומעבירים למקום פשוט, למשל `C:\mysat` ב-Windows או `~/mysat` ב-Mac.
3. בודקים שבתוך התיקייה יש קובץ בשם `platformio.ini`. אם הוא בתיקייה פנימית, זו התיקייה שצריך.

## שלב 4: לפתוח את הפרויקט

1. ב-VS Code: תפריט File, ואז Open Folder, ובוחרים את תיקיית `mysat`.
2. אם נשאלת שאלה על אמון ביוצרי התיקייה, עונים Yes.
3. בשורת המצב התחתונה PlatformIO מתחיל להגדיר את הפרויקט. בפעם הראשונה הוא מוריד את כלי הקומפילציה ל-ESP32, קרוב לג'יגה. מחכים עד ששורת המצב נרגעת. זה יכול לקחת עשר דקות.

## שלב 5: לבנות את הקושחה בלי לחבר כלום

1. לוחצים על סמל החייזר בסרגל השמאלי.
2. נפתח עץ בשם PROJECT TASKS. פותחים את `obc`, ואז `General`, ולוחצים `Build`.
3. נפתח טרמינל למטה ורצות המון שורות. בסוף צריכה להופיע שורה עם `SUCCESS` ומשך זמן.
4. אם במקום זה מופיע `FAILED`, מעתיקים את 30 השורות האחרונות ושולחים. לא ממשיכים.

## שלב 6: לחבר את ה-ESP32-CAM במצב צריבה

בדיוק כמו בקושחה המקורית, לפי "Microcontroller Setup" במדריך של הערכה. תזכורת למה שקורה שם:

1. מחברים את המתאם למחשב ולבקר.
2. מכניסים את ה-ESP32-CAM למצב צריבה: הפין IO0 מחובר ל-GND (או כפתור IO0 לחוץ, אם למתאם יש כזה) בזמן שלוחצים RESET.
3. ב-Windows: פותחים Device Manager ומוודאים שמופיע COM חדש תחת Ports. ב-Mac: בטרמינל `ls /dev/cu.*` ומחפשים usbserial. אם לא מופיע כלום, חסר דרייבר למתאם (CH340 או CP2102, לפי הצ'יפ שעליו).

## שלב 7: לצרוב את ה-ESP32-CAM

1. ב-PROJECT TASKS: `obc`, ואז `General`, ואז `Upload`.
2. בטרמינל מופיע `Connecting.....` עם נקודות. אם הנקודות נמשכות יותר מעשר שניות, לוחצים RESET על הבקר בזמן ש-IO0 עדיין מחובר ל-GND.
3. אחרי כמה עשרות שניות של אחוזים מופיע `Hash of data verified` ואז `SUCCESS`. הצריבה מכוונת למהירות איטית ובטוחה, אז קובץ של מגה לוקח בערך דקה וחצי.
4. מנתקים את IO0 מ-GND ולוחצים RESET.

## שלב 8: לצרוב את קבצי הדשבורד

לא חובה, אבל כדאי. בלי זה יש דף פנימי מצומצם שגם עובד.

1. שוב מצב צריבה כמו בשלב 6.
2. ב-PROJECT TASKS: `obc`, ואז `Platform`, ואז `Upload Filesystem Image`.
3. מחכים ל-`SUCCESS`, מנתקים IO0, לוחצים RESET.

## שלב 9: לראות שהלוויין חי

1. ב-PROJECT TASKS: `obc`, ואז `General`, ואז `Monitor`. נפתח חלון טקסט. המהירות כבר מוגדרת.
2. לוחצים RESET על הבקר. אמורות להופיע שורות, ביניהן `MYSAT OBC 2.1.0-demo` ורשימת החיישנים.
3. שורה בסגנון `assuming the stock Nano firmware` היא תקינה: הלוויין זיהה שה-Nano עדיין עם הקושחה המקורית ועובד איתה.
4. אזהרה: כ-12 שניות אחרי RESET הכנפיים נפרסות. זה רצף השיגור הרגיל. הכנפיים חייבות להיות חופשיות.
5. בחלון הזה כותבים פקודות ולוחצים Enter. כותבים `status` ומקבלים מסך טלמטריה. כותבים `help` ומקבלים את הרשימה.

## שלב 10: להפעיל את ההדגמה

1. כותבים `demo on` ולוחצים Enter. מעכשיו הוצאת הפין מריצה את ההדגמה במקום את רצף השיגור, וזה נשמר גם אחרי צריבות.
2. כותבים `demo` ורואים את לוח הזמנים: ספירה של 5 שניות, כנפיים פעמיים, אור שלוש פעמים.
3. כותבים `demo run` כדי לראות את זה עכשיו. ידיים רחוק מהכנפיים.
4. מנתקים את המתאם מהלוויין, מכניסים את הפין, מחכים כמה שניות, מוציאים את הפין. אחרי 5 שניות של הבהוב לבן פעם בשנייה, ההדגמה מתחילה.

## שלב 11 (מומלץ, לא חובה): לצרוב את ה-Nano

עם הקושחה המקורית של ה-Nano ההדגמה עובדת, אבל כל תנועת כנפיים היא סיבוב מלא עד הקצה, ואין אישור שהתנועה קרתה. הקושחה החדשה ל-Nano נותנת סיבובים עדינים שלא נתקעים בקצה, ואישור זווית אחרי כל תנועה.

1. מחברים את ה-Nano למחשב בכבל USB שלו. לא צריך מצב צריבה מיוחד.
2. ב-PROJECT TASKS: `aux`, ואז `General`, ואז `Upload`.
3. אם מופיעה שגיאה עם `not in sync`, ל-Nano שלך יש bootloader ישן. פותחים את `platformio.ini`, מחליפים `nanoatmega328new` ב-`nanoatmega328`, שומרים ומנסים שוב.
4. אחרי `SUCCESS`, לוחצים RESET על ה-ESP32-CAM. במוניטור אמורה להופיע השורה `v2 firmware detected`.

## אם משהו נתקע

- **אין COM או usbserial:** דרייבר של המתאם. מחפשים לפי הצ'יפ שעליו (CH340 או CP2102), מתקינים, מחברים מחדש.
- **`Connecting.....` בלי סוף:** הבקר לא במצב צריבה. IO0 ל-GND, ואז RESET, ומנסים שוב.
- **`Timed out waiting for packet header`:** כבל או מתאם חלשים. מנסים כבל אחר, או שקע USB אחר, לא דרך מפצל.
- **הלוויין מתאתחל בלולאה אחרי הצריבה:** בדרך כלל סוללה חלשה או כבל שלא מספק זרם. טוענים ומנסים שוב.
- **`FAILED` בבנייה:** שולחים את 30 השורות האחרונות מהטרמינל.
- **הכנפיים לא זזות בכלל:** בודקים ב-`status` את השורה `aux`. אם כתוב `no link`, ה-Nano לא מגיב ב-I2C. מוודאים שהוא דולק (הנורית שלו מהבהבת).

## פקודות שימושיות אחר כך

```
demo            # מצב ההדגמה והלוח שלה
demo run        # להריץ עכשיו
demo stop       # לעצור
demo off        # חזרה לפריסה רגילה כשמוציאים את הפין
params list     # כל ההגדרות
params set demo.light_on_ms 5000     # למשל: אור ל-5 שניות
```

הדשבורד: מתחברים לרשת ה-WiFi שהלוויין פותח, `MYSAT-1-XXXX`, וגולשים ל-`http://192.168.4.1`.
